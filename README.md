# Монитор новых проектов Kwork → Telegram

Бот раз в несколько минут смотрит первую страницу биржи Kwork в выбранных рубриках
и присылает в Telegram новые проекты, которые подходят под ваши фильтры.

Бот **только читает** публичную страницу. Он не входит в аккаунт Kwork, не откликается
и ничего не делает от вашего имени.

## Как это устроено

- Страница биржи содержит данные проектов во встроенном JSON (`window.stateData`).
  Бот берёт их оттуда: название, описание, бюджет, число откликов, % найма, время до конца.
- Без входа в аккаунт Kwork показывает только одну рубрику за запрос, поэтому каждая
  рубрика из `config.py` загружается отдельно (с паузой 3–8 сек между запросами).
- Увиденные проекты хранятся в `seen.db` (SQLite), поэтому после перезапуска повторов нет.
- При самом первом запуске бот только запоминает текущие проекты и ничего не шлёт.
- Если на первой странице рубрики все проекты оказались новыми, в лог пишется
  предупреждение: значит, интервал проверки великоват.
- Если 3 проверки подряд не нашли ни одного проекта (сайт недоступен или сменилась
  разметка), бот пришлёт предупреждение в Telegram.
- Лог пишется в `monitor.log`.

## Файлы

| Файл | Что это |
|---|---|
| `monitor.py` | сам бот |
| `config.py` | все настройки: рубрики, слова, числа — меняется кнопками в боте или вручную |
| `.env` | токен бота и chat_id (не попадает в git) |
| `.env.example` | пример `.env` без настоящих значений |
| `sample_page.html` | сохранённая страница биржи для режима `--dry-run` (не попадает в git) |
| `seen.db`, `monitor.log` | создаются автоматически |

## Фильтры

- **Рубрики** — какие рубрики Kwork проверять.
- **Ключевые слова** — хотя бы одно должно быть в названии или описании.
  Ищется часть слова без учёта регистра. Пустой список — присылать всё остальное.
- **Стоп-слова** — если встретилось, проект пропускается.
- **Макс. откликов** — не присылать, если откликов больше.
- **Мин. бюджет** — минимальный допустимый бюджет в рублях.
- **Интервал** — как часто проверять биржу, в минутах.

Все они хранятся в `config.py`. Менять их можно кнопками прямо в боте — бот сам
перепишет `config.py`. Можно и вручную в PyCharm: бот заметит изменения при
следующем нажатии кнопки или следующей проверке биржи. Перезапуск не нужен.
Если при ручной правке ошибиться в синтаксисе, бот напишет об этом в `monitor.log`
и продолжит работать со старыми настройками.

## Команда /all

Отправьте боту **/all** — он соберёт все проекты, которые сейчас висят на первых
страницах ваших рубрик и подходят под фильтры, **включая те, что уже присылал или
видел**. Самые свежие — сверху, не больше 30 штук. В конце — сколько подошло из
скольких. Занимает несколько секунд: бот загружает каждую рубрику.

## Уведомления без вибрации

Бот отправляет обычные (не «тихие») сообщения — звук и вибрацию включает
сам Telegram на телефоне, из кода ими управлять нельзя. Если вибрации нет, проверьте:

1. **Чат с ботом не заглушён.** Откройте чат → имя бота вверху → «Уведомления»
   должны быть включены (не «Без звука»).
2. **Вибрация включена в Telegram.** Настройки → Уведомления и звуки →
   Личные чаты → Вибрация (на Android ещё проверьте уведомления Telegram
   в настройках самого телефона).
3. **Telegram на компьютере.** Пока вы активны в Telegram на компьютере
   (Desktop или веб-версия), телефон обычно не звенит и не вибрирует —
   уведомление приходит туда, где вы сейчас. Сверните или закройте Telegram
   на компьютере и проверьте ещё раз.
4. **Открытый чат.** Если чат с ботом открыт на экране, уведомления не будет.

## Настройки кнопками в боте

Отправьте боту **/settings** (или выберите в меню слева от поля ввода).
Придёт сообщение с текущими настройками и кнопками:

| Кнопка | Что делает |
|---|---|
| 📂 Рубрики | разделы Kwork → рубрики с отметками ✅. Нажатие включает или выключает рубрику |
| 🔑 Ключевые слова | список слов кнопками: нажали на слово — удалили |
| ⛔ Стоп-слова | то же для стоп-слов |
| ➕ Добавить | бот попросит написать слова сообщением, можно несколько через запятую |
| ✏️ Изменить | нажмите на слово и напишите сообщением, на что его заменить |
| 🧹 Очистить весь список | пустой список ключевых слов = присылать всё, что прошло остальные фильтры |
| 🔢 Числа | макс. откликов, мин. бюджет, интервал: нажмите и напишите новое число |
| ✖️ Закрыть | убрать сообщение с настройками |

Каждое изменение сразу записывается в `config.py` и действует со следующей
проверки биржи. Новый интервал начинает работать после ближайшей проверки.

Когда вы включаете рубрику, бот запоминает проекты, которые в ней уже висят,
и присылает только новые — чтобы не прислать сразу пачку старых.

Бот слушает кнопки только из вашего чата (`TELEGRAM_CHAT_ID`), чужих игнорирует.

Кнопки работают и во время проверки биржи. Включение рубрики занимает 1–2 секунды:
бот в этот момент загружает её с Kwork. Если бот выключен, нажатия обработаются при запуске.

**Запускайте бота только в одном месте.** Две копии делят нажатия кнопок и
затирают настройки друг друга. Поэтому на одном компьютере вторая копия просто не запустится:
в консоли будет «Бот уже запущен на этом компьютере». Остановите прежнюю
(в PyCharm — красная кнопка Stop) и запустите снова.

На разных компьютерах (например, у вас и на сервере) бот так проверить не может.
Если в `monitor.log` появилось «Бот запущен дважды» — где-то работает ещё одна копия.

### Как проверить, что настройки сохраняются

Настройки лежат в файле **`config.py`** в папке бота, а все нажатия
записываются в **`monitor.log`**.

1. Отправьте боту `/settings` → «🔑 Ключевые слова» → «➕ Добавить» и напишите `проверка123`.
   Бот ответит «✅ Добавил: проверка123».
2. «« Назад» → «🔢 Числа» → «Макс. откликов» и напишите `31`. Бот ответит «✅ Макс. откликов: 31».
3. Откройте `config.py` (в PyCharm он обновится сам, на сервере — `cat config.py`). Там должно быть:

   ```python
   KEYWORDS = [
       ...
       "проверка123",
   ]
   MAX_OFFERS = 31
   ```

4. В `monitor.log` будут строки о нажатиях и вводе:

   ```
   [INFO] Кнопка: wa:k
   [INFO] Ввод: проверка123
   [INFO] Кнопка: n:o
   [INFO] Ввод: 31
   ```

   Быстро найти на сервере:

   ```bash
   grep -n "проверка123\|MAX_OFFERS" config.py
   grep "Кнопка\|Ввод" monitor.log | tail -10
   ```

5. После следующей проверки биржи в `monitor.log` у отсеянных проектов будет
   новая граница, например `откликов 45 > 31`.
6. Верните как было: удалите `проверка123` нажатием на него и поставьте 30.

Если что-то не так:

| Что видите | Причина |
|---|---|
| Бот не отвечает на `/settings` | бот не запущен — проверьте консоль или `systemctl status kwork-monitor` |
| Кнопки срабатывают через раз, долго «думают» | бот запущен дважды — оставьте один (в логе «Бот запущен дважды») |
| При запуске «Бот уже запущен на этом компьютере» | прежняя копия ещё работает — остановите её (Stop в PyCharm) |
| Подсказка «Кнопка устарела» | вы нажали кнопку в старом сообщении; отправьте `/settings` заново |
| Написали слово, бот ответил «нажмите /settings» | бот не ждал ввода — сначала нажмите «➕ Добавить» или «✏️ Изменить» |

## Запуск локально (Windows)

```bash
python -m venv .venv
.venv\Scripts\activate
pip install -r requirements.txt
copy .env.example .env
```

Впишите в `.env` свой `TELEGRAM_TOKEN` и `TELEGRAM_CHAT_ID`. Затем:

```bash
python monitor.py --test-telegram
```

Должно прийти тестовое сообщение. Проверить фильтры на сохранённой странице
(без интернета и без Telegram):

```bash
python monitor.py --dry-run
```

Можно указать другой сохранённый файл: `python monitor.py --dry-run page.html`.

Запустить бота:

```bash
python monitor.py
```

Остановить — `Ctrl+C`.

## Запуск на Bothost

[Bothost](https://bothost.ru) запускает бота из GitHub-репозитория в контейнере.
Бот уже подготовлен под него:
- токен берётся из поля **Bot Token** (Bothost передаёт его как `BOT_TOKEN`);
- база, лог и настройки хранятся в `/app/data` — это единственная папка, которая
  переживает перезапуски и обновления. При первом запуске туда копируется `config.py`
  из репозитория, и дальше кнопки в боте меняют уже эту копию.

### 1. Подготовьте код

1. Удалите `main.py` — это пустой шаблон PyCharm. Bothost сам запускает `main.py`,
   если он есть, и вместо бота запустится шаблон.
2. Проверьте, что `.env` не попадёт в репозиторий (он уже в `.gitignore`).

### 2. Выложите код на GitHub

Создайте на github.com **приватный** репозиторий (например, `kwork-monitor`), затем
в папке проекта:

```bash
git init
git add .
git commit -m "Kwork monitor"
git branch -M main
git remote add origin https://github.com/ВАШ_ЛОГИН/kwork-monitor.git
git push -u origin main
```

Для приватного репозитория Bothost нужен доступ — см. их инструкцию
[«Подключение приватного репозитория»](https://bothost.ru/docs/git-repository-access).

### 3. Заполните форму на Bothost

| Поле | Что указать |
|---|---|
| Версия Python | 3.12 (бот проверялся на ней; 3.11 тоже подойдёт) |
| Bot Token | токен от @BotFather |
| Локация | Россия (Москва) — Kwork российский сайт, так надёжнее |
| Переменные окружения | `TELEGRAM_CHAT_ID` = ваш chat_id |
| Git URL репозитория | `https://github.com/ВАШ_ЛОГИН/kwork-monitor.git` |
| Ветка | `main` |
| Главный файл (точка входа) | `monitor.py` |

`CHECK_INTERVAL_MIN` указывать не нужно — интервал хранится в `config.py`.

### 4. Запустите и проверьте

1. **Остановите бота в PyCharm.** Если он будет работать и у вас, и на Bothost,
   кнопки начнут срабатывать через раз (в логе — «Бот запущен дважды»).
2. Запустите бота на Bothost. В логах должна появиться строка:
   ```
   [INFO] Монитор запущен. Рубрик: 4, интервал: 8 мин. Настройки и база: /app/data
   ```
   Если в конце не `/app/data`, а `/app` — настройки и база будут сбрасываться,
   напишите в поддержку Bothost.
3. Отправьте боту `/settings` и `/all`.

### Как обновлять

- **Код** (`monitor.py`): поменяли у себя → `git add .`, `git commit -m "..."`,
  `git push` — Bothost сам пересоберёт и перезапустит бота.
- **Настройки**: меняйте кнопками в боте. `config.py` в репозитории после первого
  запуска не используется — правки в нём на хостинге не появятся. Нужно начать
  с настроек из репозитория — удалите `/app/data/config.py` в файловом менеджере
  Bothost и перезапустите бота.

### Тариф

На бесплатном тарифе Bothost, по их сайту, данные могут стираться при перезапуске,
а переменные окружения указаны только с тарифа Basic. Если на бесплатном нельзя
добавить `TELEGRAM_CHAT_ID` или после перезапуска сбрасываются настройки — нужен Basic.

## Где запускать бота постоянно

Бот должен работать круглосуточно: проверять биржу и слушать Telegram.
Обычный хостинг для сайтов (html/php) для этого почти всегда **не подходит**:
он запускает код только на время запроса к сайту и завершает долгие процессы.

Самый простой вариант — недорогой VPS с Ubuntu (у российских хостеров
самые дешёвые тарифы стоят несколько сотен рублей в месяц). Боту хватит самого
слабого, домен и https не нужны. Инструкция ниже.

## Запуск на VPS (Ubuntu) через systemd

Так бот работает постоянно, сам перезапускается при сбоях и после перезагрузки сервера.

1. Установите Python и скопируйте файлы проекта на сервер, например в `/opt/kwork-monitor`
   (нужны `monitor.py`, `config.py`, `requirements.txt`, `.env`):

   ```bash
   sudo apt update
   sudo apt install -y python3 python3-venv
   sudo mkdir -p /opt/kwork-monitor
   sudo chown $USER:$USER /opt/kwork-monitor
   ```

   С вашего компьютера (из папки проекта):

   ```bash
   scp monitor.py config.py requirements.txt .env user@IP_СЕРВЕРА:/opt/kwork-monitor/
   ```

2. Создайте окружение и проверьте Telegram:

   ```bash
   cd /opt/kwork-monitor
   python3 -m venv .venv
   .venv/bin/pip install -r requirements.txt
   chmod 600 .env
   .venv/bin/python monitor.py --test-telegram
   ```

3. Создайте службу:

   ```bash
   sudo nano /etc/systemd/system/kwork-monitor.service
   ```

   Вставьте (замените `user` на имя вашего пользователя на сервере):

   ```ini
   [Unit]
   Description=Kwork projects monitor
   After=network-online.target
   Wants=network-online.target

   [Service]
   User=user
   WorkingDirectory=/opt/kwork-monitor
   ExecStart=/opt/kwork-monitor/.venv/bin/python monitor.py
   Restart=always
   RestartSec=30

   [Install]
   WantedBy=multi-user.target
   ```

4. Включите и запустите:

   ```bash
   sudo systemctl daemon-reload
   sudo systemctl enable --now kwork-monitor
   ```

Полезные команды:

```bash
sudo systemctl status kwork-monitor      # работает ли
sudo systemctl restart kwork-monitor     # перезапуск (например, после обновления monitor.py)
sudo systemctl stop kwork-monitor        # остановить
tail -f /opt/kwork-monitor/monitor.log   # смотреть лог
journalctl -u kwork-monitor -f           # вывод службы, если бот не стартует
```

## Если что-то пошло не так

- **Пришло предупреждение «3 проверки подряд не нашли проектов».** Откройте `monitor.log`.
  Ошибки сети пройдут сами. Если там «нет window.stateData» — Kwork поменял страницу,
  нужно обновить разбор в `extract_projects()` в `monitor.py`.
- **В логе «все проекты на первой странице новые».** Уменьшите интервал: `/settings` → «🔢 Числа» → «Интервал».
- **Хочу заново начать с чистого листа.** Остановите бота и удалите `seen.db` —
  следующий запуск снова будет «первым» и ничего не пришлёт.
- **Бот не отвечает на кнопки.** Проверьте, что он запущен, и посмотрите `monitor.log`.
  Если в логе «Бот запущен дважды» — он запущен в двух местах
  (например, на компьютере и на VPS одновременно). Оставьте один.
